\section{Introduction}
The project is very exploratory in its nature, it was planned to be a strategy which made use of graph structure to make determinations. It has since evolved into being its own pattern as its potential value would grant greater value to the reader than the original plan. This project attempts to determine best way to design the pattern, it remains within same topic and uses graph structure with a set of rules to achieve a new system which can be used to make determinations. Therefore this project will not make direct comparisons to already existing solutions as optimisation will have very little influence on this project.

This article will go through the same order which I made the project, you will notice a change in focus on the topics quickly after the related work section and start of development, as while the analysis of how the code should be implemented remained much the same, the concern of the project changed from "How much can this idea compete with other solutions" to "How does it fit in with other software patterns?". You may see how the research questions do relate to both of these.
	
Modern machine learning systems has a certain level of uncertainty. Developers cannot always explain how a model makes its determinations. This makes it challenging for developers to understand how the system operates internally, verify the results, or ensure the verifiability of the outcomes.

To address these challenges, I present \gls{reps}, a graph-based real-time analysis tool which developers themselves can design to fit their use case while making use of many state-of-the-art machine learning models. \gls{reps} operates by processing input data, which is likely will be sensor data which will pass through nodes called "event nodes". Each node processes inputs from one or more sources and generates a result that can be used on one or multiple downstream nodes. This system enables	real-time decision-making across interconnected components while still allowing the developer to know how it operates.

This project aims to determine whether there are any viable use cases for \gls{reps} and what advantages and disadvantages it may have.

\subsection{Problem}\label{sec:RQProblem}
Research Questions:
	\begin{itemize}
		\item RQ0: How should a \gls{reps} be constructed?
		\item RQ1: What advantages and disadvantages does \gls{reps} have compared to other solutions?
	\end{itemize}
	
\noindent
Research Question mapping:
	\begin{itemize}
		\item  RQ0: How a \gls{reps} should be constructed can be determined based on the experienced gained by implementing one, thereby this can be answered once the development phase has completed. This question brings the value of hasten implementation of same or similar systems while allowing for them to avoid the mistakes made in this project.
		\item RQ1: If a \gls{reps} should be implemented in company environment, it should bring a value to the company. Therefore a comparison with similar solutions has to be made to allow engineers to compare \gls{reps} with other solutions. To make this determination, comparisons between other solutions will be made in terms of memory usage, CPU usage, to what degree it can make determinations and other relevant metrics.
	\end{itemize}
